# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

A single-binary open-captioning server for community theater (Go 1.26+, no CGO). One host serves three web UIs: `/admin` (Setup wizard), `/operator` (spacebar advances the caption), and the audience page. Module path: `github.com/tmshort/open-caption`.

## Commands

`make help` lists every target (a bare `make` does the same); the ones below are the common ones.

- `build.bat` (runs `build.ps1`) is `make build` for Windows, which has no make; `deploy/deploy_test.go` checks it uses the Makefile's default providers and flags, so change both together.
- `make build` → `bin/open-caption`; run `./bin/open-caption` (first run writes `config.yaml` with random passwords; `--show-file` flag exists).
- `make test` / `make race` (`go test -race ./...`) / `make vet`
- Single test: `go test ./internal/httpapi -run TestName -count=1`
- `make fuzz` fuzzes the show-file parser (`FuzzParse`)
- `make e2e` — browser end-to-end suite (`test/e2e/run.js`, puppeteer-core; needs Node and Chrome, set `CHROME` if not at the default path). Chrome allows 6 connections per host, so e2e pages must be closed when finished (SSE streams stay open).
- Log with `internal/logx` (`logx.Infof/Warnf/Errorf/Debugf`), not `log.Printf`; level comes from `log.level` / `--log-level`.
- `config.Load` is strict (unknown YAML keys are errors) and reports all problems at once via `*config.ProblemsError`; add new settings to `normalize()`.
- `tools/make-icons.js` regenerates `favicon.ico` / `apple-touch-icon.png` from `web/shared/favicon.svg`.
- `make dist` cross-compiles release binaries (CGO disabled). **Releases:** push a `v1.2.3` tag and `.github/workflows/release.yml` runs `make release` (pinned GoReleaser, `.goreleaser.yaml`) to make a draft GitHub release with a download per platform; `make release-snapshot` tries it locally, `GITHUB_TOKEN=$(gh auth token) make release` releases from this computer (`docs/releasing.md`). What goes in a download is the `files:` list in `.goreleaser.yaml` (guides yes, design specs `01`–`09` no); wrap README parts that only make sense next to the source in `<!-- source-only:start -->` / `<!-- source-only:end -->`; `go test ./deploy` checks the download for dead links.

Run `gofmt`, `go vet ./...` and `go test -race ./...` before committing (the full list, and the documentation rules, are under "Commits and documentation").

Outside contributions: `CONTRIBUTING.md` (no code PRs accepted yet; DCO sign-off with `git commit -s`; keep its rules and the "Commits and documentation" section below in step).

## Spec-driven

`docs/` is the source of truth (the README's *Spec-driven workflow* table lists the specifications `01`–`10`; its *Documentation* table lists the guides for users); change the spec in the same commit as behavior. Requirements are numbered `REQ-xxx`; reference them from tests and commits. Terminology: the text file a show is written in is the **show file** — never "script".

## Commits and documentation (always)

- **One fix or feature per commit.** Never bundle two changes: if a request has several parts, make several commits, each complete on its own (code, tests, docs, translations). Don't mix refactors or unrelated tidying into a feature or fix; give them their own commit. Commit messages say what changed and why, reference `REQ-xxx` where there is one, and end with the co-author line.
- **The documentation changes in the same commit as the behavior, never later.** Before committing, go through this list and update every place the change touches:
  - the spec in `docs/` (requirements `01`, architecture `02`, show file `03`, API `04`, UI `05`, deployment `06`, testing `07`, roadmap `08`, open questions `09`) and the specific guides (`10` certificates, `configuration-reference.md`, `usage-guide.md`, `venue-network-guide.md`, `https-certificate-guide.md`, and the English-only bare-computer build guides `build-macos.md`, `build-windows.md`, `build-linux.md`, which must be updated when the build requirements change: Go version, Node version, tools);
  - `README.md` (features, quick start, building, the docs table) and this file;
  - the man page `docs/open-caption.1` and the `--help` text for any command-line option (a test checks they agree with `docs/configuration-reference.md`); a new `config.yaml` setting goes in `docs/configuration-reference.md` (a test checks every key is described);
  - the in-app help (`web/help/*.md`) and the **translations**: help topics in `web/help/<lang>/` and guides (usage, venue network, HTTPS certificate, configuration reference) in `docs/i18n/<lang>/` for es, fr, de, it, pt, and on-screen text via `__('…')` in `web/shared/i18n/<lang>.js` (`node test/e2e/check-i18n.js`);
  - tests, including the browser checks in `test/e2e/run.js` and the accessibility audit when a page changes.
  If a document is English only by design (`docs/10`, the man page), say so where it is linked rather than leaving it untranslated silently.
- **Verify before every commit:** `gofmt`, `go vet ./...`, `go test -race ./...`, and for anything that touches the web pages `make e2e`, `node test/e2e/a11y.js` and `node test/e2e/check-i18n.js`; `make vulncheck` after changing dependencies. Then `git pull --rebase` and push.
- Don't leave a change half-documented "for a follow-up": if the documentation can't be finished with the change, the change isn't finished.

## Architecture (needs several files to see)

- **`internal/showfile`**: parser for the Markdown-subset show file (one line = one caption; directives like `[clear] [image] [loop] [song] [together] [language] [settings]`). Produces `Cue`s plus diagnostics with line numbers; `CompareStructure` checks a translation matches the main language cue-for-cue. `settings.go` parses and rewrites the `[settings]` block (`UpdateSettings` / `ReplaceSettings` keep everything else in the file byte-for-byte).
- **`internal/show`**: on-disk store, `<data-dir>/shows/<id>/` holding `show.md` (main language), `show.<lang>.md` (translations) and `assets/`. There is no separate metadata file: the title, look, idle message(s), loop time and scrollback size are all in the show file's `[settings]`.
- **Configuration layering**: built-in defaults (`config.Default`) < `config.yaml` (`defaults`, `defaults.look`, `audience.scrollback_lines`) < show file `[settings]`. `show.Defaults.Resolve` does the layering; `httpapi.showDefaults(cfg)` builds the defaults. Environment-only settings (ports, HTTPS, passwords, access lists, data dir) live in `config.yaml` only. Look/Rename in Setup write the show file; a translation's file may set only `idle message`.
- **`internal/live`**: the per-language caption `Engine` (cursor, scrollback, loops, undo, blank/clear). Pure state machine; emits events via a callback. `Engine.Configure` changes loop time/scrollback on a running engine.
- **`internal/hub`**: fan-out of SSE events to audience/operator connections for one language. Clients subscribe first, then receive a snapshot (ordering matters for not missing events); `seq` orders audience events, `rev` orders operator commands.
- **`internal/httpapi`**: `Server` (routes, auth, Origin/Sec-Fetch-Site guard, access allow-lists), `Runtime` (the active show: one engine + hub per language, driven in lockstep by `Runtime.Do`; persists to `live.json`), and `admin.go`/`operator.go`/`audience.go` handlers. `Server.applyActive(id)` is how any change to the show on air (look, title, loop time, every language's lines) reaches the runtime — call it after saving show files or settings.
- **`internal/acme`**: automatic HTTPS certificates (ACME DNS-01; `docs/10`). `Manager` (no protocol knowledge) keeps the certificate current through an `Issuer`; the lego-based `Issuer` is only compiled in with the DNS providers the builder chose: no tags = Cloudflare, GoDaddy, EasyDNS (`prov_*.go`), `acme_off` = none, `acme_custom` = the generated `zz_providers_gen.go` that `tools/acme-go.sh` writes (the Makefile's `ACME_PROVIDERS`; names outside the default list use a copy of go.mod, `go.acme.mod`, so the real go.mod stays small). Credentials (environment / `credentials_file` / config) are never logged, bundled (`Config.Redacted`) or sent to Setup. `make acme-variants` compiles every choice; `go test -tags pebble` runs the real path against Pebble (run it with `make pebble-test`, which installs the Pebble version pinned in the Makefile; test tools are pinned there, except `govulncheck`, which must stay current).
- **`internal/check`**: the show-file analysis shared by Setup's editor (`httpapi.analyze`) and the command line `open-caption --check-show FILE [translations]` (`check.Run`: `file:line: severity: message`, exit 0/1/2; the parsing itself is `internal/showfile`). Keep the two on the same code; the report text is English.
- **Offered addresses (REQ-069):** `netinfo.AllAddresses` lists the addresses of interfaces that are *up* (Windows reports a switched-off adapter's last address otherwise), main connection first, each with its adapter kind (`kind_*.go`: Windows adapter type, `networksetup`, `/sys/class/net`, else the name); `netinfo.LocalIPs` is that less the `network.include`/`network.exclude` filter, and only one address per network (`network.prefer`, else main connection, wired, other, Wi-Fi; `netinfo.Offered` is what the `.local` announcement uses) (`config.AddressFilter`, set with `Server.ApplyNetwork`, from config, `--network-include/--network-exclude` or Setup → Settings → Network). It decides the startup URLs, Setup's list, the self-signed certificate and the `.local` announcement (`mdns.Start(name, netinfo.Allowed)`), and with `network.restrict_listening` (`netinfo.LimitListener`, wrapped around the wildcard listeners in `main`) connections made to an address that is not offered are closed — loopback is always served, and `setNetwork` refuses any lists that would turn off the address the request came in on (409; none for localhost). Otherwise it does not decide who may connect (`ownHost` uses all addresses).
- **`internal/config`**: `config.yaml` load/validation and access lists. **`internal/help`**: embedded in-app help (a test checks every show-file convention and setting name is documented in `web/help/*.md`).
- **`web/`** is embedded with `go:embed`: `admin/`, `operator/`, `audience/` (plain JS, no build step), `help/`, `sample/` (sample show, English + Spanish), fonts. Nothing is fetched from the internet at runtime.

## Things to remember

- Setup and the operator page share `web/shared/ui.css` (type, headings, links, buttons, text boxes, focus ring, hints, sign-in panel, dialogs, help panel, toast) and `header.css`; each page defines only its **palette** (`--bg --panel --fg --dim --line --control --input --accent --accent-fg --ok --warn --bad`; the operator adds `--mark`, the yellow of "next"/speakers/warnings) and its own layout. Don't restyle a control in a page's CSS; change `ui.css`. The operator's "stage scale" (lines, banner, footer controls a size larger) is the one deliberate difference.
- Setup's and the operator page's headers share `web/shared/header.css` (size, spacing, pills, quiet links, language menu, connection dot); change header looks there, not in the page CSS (a browser test compares the two).
- **Connections:** a browser allows six per address and every open page holds an SSE stream, so each page (`operator.js`, `admin.js`, `audience.js`) closes its stream on `pagehide` and reopens it on `pageshow` when restored from the back/forward cache; without that, going back and forth between Setup and the operator page leaked streams until the next page hung (the browser test "moving quickly back and forth" guards it).
- **Standby / on air (REQ-066):** in production (`Server.EnableStandby`, off for `--dev`) a loaded show starts in standby: `live.Engine` keeps its real state but `view()` tells the audience `mode: "standby"` with no lines, so nothing of the show leaks. `Start` (`POST /api/operator/onair`) puts it on air (and starts a leading loop), `OffAir` returns to standby keeping the position, `Reset` goes back to the start *and* standby, and commands that change the audience's screen return `ErrStandby` (409) until started. **Live = on air**, so a show in standby can be edited, deleted or replaced freely. The standby screen (logo file `standby-logo.<ext>` in the data folder + `standby.message` in `config.yaml`) is venue-level (`internal/httpapi/standby.go`). Tests and automation can pass `start: true` to activate; the browser test's activations do.
- **Local auto sign-in (REQ-067):** `Server.require` signs a browser on this computer in as admin without a password when `Server.localTrusted` says so (loopback connection + loopback `Host` + no proxy headers + no cross-site `Sec-Fetch-Site`; `access.local_auto_login`). The session is marked `auto`, so the pages hide Sign out. `testConfig()` turns it off because the tests' client is on 127.0.0.1, as do the browser tests (except their last section).
- Show-file edits while live require confirmation (typing the show name); the cursor is kept by cue index. Saving the look is refused when the editor has unsaved changes (it rewrites the saved file).
- Archiving a show is the `archived: yes` setting in its show file (`Store.SetArchived`); archived shows cannot be activated.
- The audience page keeps the screen on with the Wake Lock API, or a tiny looping video (`web/audience/nosleep.*`) where that API is missing (plain HTTP).
- Browser floor: `web/shared/compat.js` (plain ES5, loaded first on every page) gates old browsers and fills in `<dialog>`/`replaceChildren`; `test/e2e/check-compat.js` keeps JS at ES2018 and CSS free of newer features (the audience page also avoids `inset` and flex `gap`). Page CSPs forbid `eval`/`new Function`.
- `internal/mdns` announces `<name>.local` (own minimal responder over `golang.org/x/net`, IPv4 only, probes for name conflicts); `httpapi/mdns.go` runs it and the name row of the Run step's address list changes it (`nameRows` in `admin.js`). The real network is only touched from `main`, never in tests (`fakeResponder`, the in-memory `bus`).
- UI language (Setup, operator, Help): wrap every on-screen English literal in `__('…')` (`{name}` placeholders: `__('Hi {name}', {name})`); `web/shared/i18n/<es|fr|de|it|pt>.js` map English → translation. `node test/e2e/check-i18n.js --list` shows what needs translating (it also reads the Go error/diagnostic strings and `i18n-tables.json`/`i18n-extra.json` for strings reached through variables); the e2e run fails if any language lacks one.
- Documentation is translated too: an English change to a help topic (`web/help/*.md`) or guide (`docs/*.md`) needs the same change in `web/help/<lang>/` / `docs/i18n/<lang>/` (es fr de it pt). `go test ./internal/help` checks each translation has the same headings, tables, links and byte-identical code blocks as the English; heading ids (for `#anchor` links) are the translated heading without accents (`help.Slug`).
- `node test/e2e/a11y.js` is the accessibility audit (axe-core + reflow + focus); keep it at zero violations: every page needs a `main` landmark (login panels are `<main hidden>`), labelled controls, and 4.5:1 text contrast in both colour schemes.
- Sessions persist hashed in `sessions.json`; per-language live state in `live.json`.
- Multi-language: one operator keypress advances every language, so structure mismatches are errors and the mismatching translation is not served.
